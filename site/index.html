A 1970s Data Workstation. Any engine. Process anything. Locally.

What would processing big data on a 1970s computer feel like? Notisbook is a Data Workstation from an alternate timeline, where the engines already sit in the cabinet. Spark (local, or AWS Glue 5.0 in Docker) and DuckDB run side by side as runtimes; Delta Lake, Apache Iceberg, Apache Hudi and Parquet are the table formats. Every table lands in a persistent catalog organized in bronze, silver and gold, and other engines may join later. Everything listens on 127.0.0.1.

SECTION 1 · OPERATING PROCEDURE

Three steps from power-on to a cataloged table.

No cluster to provision and no cloud account to configure. No machine room either. Notisbook installs the runtimes, picks the JDK for Spark, starts the storage and registers what your cells create.

  1. 01load

    Load the system with one line

    The installer checks the sha256 of the wheel, the constraints file and the MinIO tarball before installing anything, like an operator verifying the tape. Then it places the notislake on your machine.

    $ curl -LsSf …/install.sh | sh
  2. 02configure

    Mount a runtime

    Each runtime gets its own isolated environment and kernel, like a partition of its own. Spark is versioned per line, with Delta, Iceberg, Hudi and S3A jars verified by sha256 and the JDK selected for you; AWS Glue 5.0 runs in a local Docker container; DuckDB 2.0.1 ships with its extensions pinned by sha256 (httpfs, iceberg, avro, excel, sqlite_scanner, postgres_scanner, spatial).

    › spark 3.5.9 · jdk 17      ✓
› glue 5.0 · docker        ✓
› duckdb 2.0.1 · 7 ext   ✓
  3. 03run job

    Submit cells, get cataloged tables

    After each cell the catalog is reconciled, like a batch job closing its log: tables written by Spark or DuckDB appear in the Catalog panel, with their files in s3a://notislake/<layer>/. The schema decides the layer.

    .saveAsTable("bronze.orders")
→ Catalog › spark › bronze
CREATE TABLE notislake.bronze.orders AS …
→ Catalog › iceberg › bronze

How it works

  • Reconciled after every cell. A catalog hook records table creations, changes, renames and deletions, and picks up writes made by other kernels before the next cell.
  • Layers enforced. Managed tables live at s3a://notislake/<layer>/<table>. The schema decides the layer, and a write to the wrong layer fails before any data is written.
  • Schemas without a kernel. Browse catalogs and columns, and create or delete schemas from the UI without starting any session.
  • Same catalog in Docker and DuckDB. The AWS Glue container reaches the catalog through /api/runtime-catalog and the Iceberg REST catalog; the DuckDB kernel attaches the same Iceberg REST catalog. Both are authenticated by a per-session token.

SECTION 3 · SYSTEM INVENTORY

Everything the system needs, already wired. No cables.

Persistent catalog

Delta, Parquet and Hudi tables created by notebooks are kept in catalog.db (SQLite) and listed without an open kernel. Iceberg has its own iceberg catalog, also served over REST to the Glue container and the DuckDB kernel.

Delta, Iceberg and Hudi

A bundle matrix per Spark line (3.5 and 4.1) pins the Delta Lake, Iceberg, Hudi and Hadoop/S3A jars, each verified by sha256.

5.0

AWS Glue runtime in Docker

Optional kernel on the AWS Glue 5.0 image: Spark 3.5, Python 3.11, Java 17, with Delta and Iceberg, running in a persistent local container.

2.0.1

DuckDB runtime

Its own environment and kernel, no JVM needed. The httpfs, iceberg, avro, excel, sqlite_scanner, postgres_scanner and spatial extensions are pinned by sha256; Iceberg tables go through the app's REST catalog.

notislake

A local MinIO, started and supervised by Notisbook, serves the notislake bucket over s3a://: bronze, silver and gold are the cataloged layers, and landing is a free zone outside the catalog for raw files. A manual S3 endpoint can be used instead.

pysqlduckdb

Python, Spark SQL and DuckDB

Edit .ipynb notebooks in the browser. The local Spark kernel runs Python, Spark SQL and DuckDB cells (DuckDB in-process, without the catalog); the Glue kernel runs Python and Spark SQL; the DuckDB kernel runs Python and DuckDB cells on the notislake catalog.

⇧↵⌘↵Esc

Keyboard-first cells

Shift+Enter runs a cell and moves to the next one; ⌘Enter runs it and stays. A Jupyter-style command mode adds Esc/Enter, J/K to move, A/B to insert, M/Y to convert and D D to delete.

md⌘.

Markdown, titles and focus

Mix markdown cells with code, give any cell an optional title and press ⌘. to switch to focus mode, with the side panels hidden.

recent

Recent notebooks

The home screen lists your 5 most recently opened notebooks, like the last jobs in the queue, so you pick up where you left off.

3.54.1JDK

Versioned Spark environments

Each Spark version is installed in its own environment (Python 3.12 via uv). The JDK is picked per line: 17 for Spark 3.x, 21 or 17 for Spark 4.x. A failed reinstall keeps the previous one.

uv pip

Library management

Install, upgrade and remove Python libraries in a Spark environment from the UI.

.py.ipynb.html

Export

Export notebooks to .py (Databricks notebook source), .ipynb and an HTML report without JavaScript.

127.0.0.1

Local-only by design

Fixed loopback bind, a random token per startup, Host/Origin checks and a strict CSP with sanitized HTML outputs.

SECTION 5 · LOADING THE SYSTEM

Boot sequence: one command.

1 · Install or update

zsh
$ curl -LsSf https://github.com/ROM-mm/Notisbook/releases/latest/download/install.sh | sh

Run the same command again to update. Pin a release with sh -s -- --version X.Y.Z or NOTISBOOK_VERSION=X.Y.Z.

2 · Boot

zsh
$ notisbook

Starts the backend on http://127.0.0.1:8765, prints the address with a per-startup token and opens your browser. The first run seeds the Delta, Hudi, Iceberg, Glue and DuckDB samples. To check the bundled notislake without starting a server, run notisbook --check-notislake.

3 · Optional: AWS Glue base image

zsh
$ docker pull public.ecr.aws/glue/aws-glue-libs:5@sha256:a54bd25fb72c55a2f28d07656a3cda943a042f345cc25f4c2c170667be864f01

Uninstall

zsh
$ notisbook uninstall

Removes Notisbook and keeps your data in ~/.notisbook.

Requirements

  • macOS on Apple silicon or Intel.
  • curl (or wget), awk and shasum.
  • uv 0.8.4 or newer (installed automatically if missing).
  • Only for Spark runtimes: JDK 17 for Spark 3.x; JDK 21 (or 17) for Spark 4.x.
  • For the Glue runtime: Docker (for example via Colima) and about 15 GiB of free disk.
